# Existing project

Use when the code already exists (yours, a teammate’s, a fork).

1. Classify the session: read-only, one change, or make it agent-ready.
2. Fill **checklist.pdf**. Name files that may change and what must not change.
3. Inventory first: README, how to test, layout, git status.
4. Trust running code over stale docs.
5. Change the system that is there. Do not generate a parallel architecture.
6. No rename, new dependency, or rewrite unless you decided it.
7. Run this project’s own tests. You review. You merge.
