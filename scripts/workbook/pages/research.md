# Research and chat

Use when you want an answer, not a code change.

1. Write the question and what must not happen (even one line).
2. Pick the output: answer, plan, map, or sources.
3. Do not create files, install tools, or commit.
4. Prefer current docs over memory. Label guesses.
5. If you decide to build it, stop. Switch to **new.pdf** or **inherited.pdf** and fill the checklist.

Close with one next action you can copy, not a pep talk.
